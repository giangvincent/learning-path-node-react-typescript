Lesson 14b · Week 4–5 · about 20 minutes · one new thing, short

Off the wire

A short sitting with one decision: delete familyId from PersonResource. It is a field the client has never read, that cannot be used, and whose only future is to tempt a route that should not exist. The deletion is compiler-enforced, which is the whole point.

Mission: ship KinLink Requires: Lesson 14a Reference: 04 Practice: Lesson 14d
The win

PersonResource and FamilyResource agree: a client never holds a family id it cannot safely hand back. npm run typecheck exits 0 — and would have failed if the field were not truly gone from both sides.

Build it

  1. Take the family id off the wire

    PersonResource has shipped familyId since lesson 02, and grep -rn familyId client/src finds nothing: the client has never read it. It is a field that cannot be used (the routes take a slug), and its only future is to tempt an endpoint that accepts a family id — the thing Reference 04 forbids. Lesson 13b's FamilyResource drops the family id on exactly this argument, so the two views disagree with each other.

    shared/contracts/person.ts 
    export interface PersonResource {
  id: string;
  name: string;
  living: boolean;
}
    server/src/views/person.view.ts 
    export function toPersonResource(person: Person): PersonResource {
  return {
    id: person.id,
    name: person.displayName,
    living: person.deathDate === null,
  };
}
    Why this deletion is compiler-enforced

    toPersonResource has an annotated return type, so the object literal is checked against PersonResource. Put familyId back and npm run typecheck fails. Contrast the session-11 blind spot: a Prisma select with a where beside it hid a dead column from the compiler for a month. The view is checked; the query was not. Measured, in Lesson 14d.

    One caveat for the interview. Removing a field from a response is a breaking change for a consumer you do not control. Here the only consumer is this repository, and it never read the field — so this is safe. In a public API you would version it, or keep it and stop promising it. Say the caveat out loud rather than skipping to "the compiler was fine".

Verify (after)

npm run typecheck        # exit 0
grep -rn familyId client/src   # no matches — nothing read it

Lesson 14d's break-it puts familyId back and shows the TS2353 that proves the deletion is real.
