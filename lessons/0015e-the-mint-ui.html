Lesson 15e · Week 5 · ≈ one session · one new thing

The mint UI, through the transport

The server can mint, list, revoke and resend. The client can only list. InviteDialog was supposed to be the mint screen, but it is imported by nothing and posts to a route that does not exist. Delete it and build the real one — posting through the transport, which uncovers a route that skipped the response envelope.

Mission: ship KinLink Requires: Lesson 15d References: 12 · 09 Practice: Lesson 15f
The win

An owner fills a small form, the server mints, and the invite link is shown once — the only time that credential will ever exist. The dead InviteDialog is gone, and every client request now goes through lib/api.ts.

Warm-up: what does the transport expect back?

From memory: after a successful request, what exact JSON shape does request<T> unwrap? Then read the mint handler in invitation.routes.ts. Do this before the first step — there is a mismatch.

Build it

  1. Verify the baseline, and find the envelope bug

    npm run typecheck        # exit 0
grep -rn "InviteDialog" client/src   # imported by nothing (dead)
grep -rn "fetch(" client/src         # only lib/api.ts after 15d

    Now look at what the mint and resend routes return: res.status(201).json({ token }) — a bare body. But request<T> does (await response.json()).data. Through the transport, that call returns undefined. Every other route wraps its payload in { data: … }; these two forgot. The transport owns the envelope — a route that skips it is a bug the client cannot fix.

  2. Put the two routes back under the envelope

    server/src/routes/invitation.routes.ts (mint and resend responses) 
        // mint handler:
    res.status(201).json({ data: { token: result.token } });

    // resend handler:
    res.status(201).json({ data: { token: result.token } });

    Then name the shape in the contract so both sides compile against it — and register it, because the client's re-export list is explicit, not a wildcard:

    shared/contracts/invitation.ts (addition) 
    /** The raw token, returned exactly once at mint and resend. Never stored. */
export interface CreatedInvitation {
  token: string;
}
    client/src/contracts.ts (addition) 
    export type { CreatedInvitation } from "../../shared/contracts/invitation";

    Skip that re-export and typecheck fails with TS2305: Module '"../contracts"' has no exported member 'CreatedInvitation' — the compiler catching the missing wire, which is the whole point of an explicit list.

  3. Delete the dead dialog, add the transport call

    terminal 
    rm client/src/InviteDialog.tsx
    client/src/lib/api.ts (addition) 
    // Add CreatedInvitation to the existing type import from "../contracts", then:

export function createInvitation(
  slug: string,
  input: { email: string | null; role: "member" | "admin" },
): Promise<CreatedInvitation> {
  return request<CreatedInvitation>(
    `/api/families/${encodeURIComponent(slug)}/invitations`,
    { method: "POST", body: input },
  );
}

    Note what this fixes by construction: the old dialog posted to /api/invitations (no POST / handler → 404) and used a raw fetch. The real path is family-scoped, and the transport adds the credentials and the envelope.

  4. The form, and the one-time link

    Replace InvitesPage.tsx with a version that renders the list plus a mint form. Give the list a reload counter so minting refreshes it without a full reload.

    client/src/InvitesPage.tsx (rewritten) 
    import { useEffect, useState } from "react";
import type { FormEvent } from "react";
import { useParams } from "react-router-dom";
import type { InvitationResource } from "./contracts";
import { ApiError, createInvitation, getInvitations } from "./lib/api";

function addressee(invitation: InvitationResource): string {
  return invitation.email ?? "Anyone with the link";
}

function MintInvite({
  slug,
  onMinted,
}: {
  slug: string;
  onMinted: () => void;
}) {
  const [email, setEmail] = useState("");
  const [role, setRole] = useState<"member" | "admin">("member");
  const [token, setToken] = useState<string | null>(null);
  const [error, setError] = useState<string | null>(null);

  const submit = async (event: FormEvent) => {
    event.preventDefault();
    setError(null);
    try {
      const created = await createInvitation(slug, {
        email: email.trim() === "" ? null : email.trim(),
        role,
      });
      setToken(created.token);
      onMinted();
    } catch (cause) {
      if (cause instanceof ApiError && cause.status === 409) {
        setError("That email already has a pending invitation.");
      } else if (cause instanceof ApiError && cause.status === 403) {
        setError("You need to be an owner to invite.");
      } else {
        setError("Could not send the invitation.");
      }
    }
  };

  return (
    <form onSubmit={submit}>
      <input
        value={email}
        onChange={(e) => setEmail(e.target.value)}
        placeholder="email (blank = shareable link)"
      />
      <select
        value={role}
        onChange={(e) => setRole(e.target.value as "member" | "admin")}
      >
        <option value="member">member</option>
        <option value="admin">admin</option>
      </select>
      <button type="submit">Send invite</button>

      {error && <p role="alert">{error}</p>}
      {token && (
        <p>
          Share once — this is the only time it is shown:{" "}
          <code>{window.location.origin}/invite/{token}</code>
        </p>
      )}
    </form>
  );
}

export default function InvitesPage() {
  const { slug } = useParams<{ slug: string }>();
  const [invitations, setInvitations] = useState<InvitationResource[] | null>(
    null,
  );
  const [error, setError] = useState<string | null>(null);
  const [nonce, setNonce] = useState(0);

  useEffect(() => {
    if (!slug) return;
    getInvitations(slug)
      .then(setInvitations)
      .catch((cause: unknown) =>
        setError(cause instanceof Error ? cause.message : "Unknown error"),
      );
  }, [slug, nonce]);

  if (!slug) return <p>No family in the URL.</p>;

  return (
    <main style={{ fontFamily: "system-ui, sans-serif", padding: "2rem" }}>
      <h1>Pending invitations</h1>
      <MintInvite slug={slug} onMinted={() => setNonce((n) => n + 1)} />
      {error && <p role="alert">Failed to load: {error}</p>}
      {!error && invitations === null && <p>Loading…</p>}
      {invitations?.length === 0 && <p>No pending invitations.</p>}
      {invitations && invitations.length > 0 && (
        <ul>
          {invitations.map((invitation) => (
            <li key={invitation.id}>
              {addressee(invitation)} — {invitation.role} — sent{" "}
              {new Date(invitation.createdAt).toLocaleDateString()}
            </li>
          ))}
        </ul>
      )}
    </main>
  );
}
    The token is shown once, and only a link

    The raw token exists for this one response. Do not stash it in a store, a query cache, or localStorage — a persisted raw credential is exactly what hash-at-rest avoided. If the owner loses the link, the answer is resend (15c), not "show it again."
