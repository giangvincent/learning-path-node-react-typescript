The proof

Lesson 14a established a rule with a sharp edge — a 401 ends the session when it is about the session, and never when it is about the input. A sharp edge deserves a proof. This sitting adds the project's first client-side check: it stubs fetch, needs no test framework, and pins the rule.

The win

npm run check:session — a client-side check that stubs fetch, needs no server and no database, and prints 1 / 0 / 0: a session-carrying 401 announces, a sign-in 401 does not, a 500 does not.

Build it

  1. The check, with no test framework

    The rule you implemented in 14a has a sharp edge — the sign-in exception — and a sharp edge deserves a proof. The server's check:* scripts need no framework, and neither does this one: request() talks to global fetch, so the check replaces fetch and inspects what the transport announced. No DOM, no React, no port, no database.

    client/src/scripts/checkSessionEnd.ts (new) 
    import { onSessionEnded } from "../lib/session.js";
import { ApiError, getFamilies, login } from "../lib/api.js";

// The first runnable check that lives on the client, and it needs no test
// framework: `request` talks to global fetch, so this replaces fetch and then
// inspects what the transport announced. No DOM, no React, no port, no database.
//
// The claim under test is narrow and worth being precise about: a 401 must end
// the session when it is ABOUT the session, and must never end it when it is
// about the input. Same status code, opposite consequences.
async function main(): Promise<void> {
  let announcements = 0;
  const unsubscribe = onSessionEnded(() => {
    announcements += 1;
  });

  const respondWith = (status: number): void => {
    globalThis.fetch = (async () =>
      new Response("{}", { status })) as unknown as typeof fetch;
  };

  const swallowApiError = (work: Promise<unknown>): Promise<void> =>
    work.then(
      () => undefined,
      (cause: unknown) => {
        if (!(cause instanceof ApiError)) throw cause;
      },
    );

  respondWith(401);
  await swallowApiError(getFamilies());
  console.log(`401 on a session-carrying read -> announced: ${announcements}`);

  const beforeSignIn = announcements;
  await swallowApiError(login({ email: "nobody@probe.invalid", password: "no" }));
  console.log(
    `401 on a sign-in attempt        -> announced: ${announcements - beforeSignIn}`,
  );

  const beforeFault = announcements;
  respondWith(500);
  await swallowApiError(getFamilies());
  console.log(
    `500 on a session-carrying read  -> announced: ${announcements - beforeFault}`,
  );

  unsubscribe();

  if (announcements !== 1) {
    throw new Error(
      `EXPECTED exactly 1 announcement, got ${announcements}: a 401 must end the ` +
        `session when it is about the session, and never when it is about input`,
    );
  }

  console.log(
    "\nsession-end announcement is scoped to the session, not to 401",
  );
}

await main();

    The first version of this file did not compile (measured)

    It ended with the familiar main().catch((error) => { console.error(error); process.exitCode = 1; }). npm run typecheck answered: client/src/scripts/checkSessionEnd.ts(63,3): error TS2591: Cannot find name 'process'. This file lives in the client's program, whose types are the browser's — types: ["vite/client"] plus the DOM lib, and no Node types on purpose, so a component can never reach process or fs. Do not "fix" it by adding "node" to that list; that would hand every component Node APIs to make one script compile. The check fails the honest way instead: it throws, and Node's default unhandled-rejection behaviour makes that a non-zero exit.

    This is also why the file lives at client/src/scripts/ and not client/scripts/: the client tsconfig includes ["src"], so anything outside it is not compiled at all — silently. Lesson 05's trap, one folder over.

`check:session` needs no MySQL — so run it constantly

It stubs fetch and touches no server. Together with check:guards, that is the cheap half of the testing pyramid: npm run typecheck && npm run check:guards && npm run check:session finishes in about a second and catches the whole class of "the wiring is wrong" bugs — including the one lesson 14a fixes.
